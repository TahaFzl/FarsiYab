# جست‌وجوی وب (Brave Search API)

- **شناسه در کد:** `brave_search` (نتایج بر اساس دامنه‌ی مقصد به سورس‌های `instagram`، `facebook`، `website` یا `directory:*` نسبت داده می‌شوند)
- **وضعیت:** ⏸ **اختیاری** (نیاز به حساب و کارت بانکی دارد؛ [ADR-005](../decisions/005-no-account-sources-first.md)). در MVP، کشف فیس‌بوک و اینستاگرام از طریق [Overture](overture-maps.md) انجام می‌شود.
- **نوع دسترسی:** API رسمی
- **مستندات:** https://api-dashboard.search.brave.com/app/documentation
- **قیمت:** https://api-dashboard.search.brave.com/documentation/pricing
- **احراز هویت:** API key (با ثبت کارت بانکی)

## چرا این سورس مهم است
اینستاگرام و فیس‌بوک **API جست‌وجوی عمومی ندارند** و اسکرپینگشان ممنوع است. ولی صفحات عمومی آن‌ها توسط موتورهای جست‌وجو ایندکس می‌شوند. با کوئری‌هایی مثل

```
site:instagram.com "Toronto" (ایرانی OR Persian OR Iranian) restaurant
```

می‌توانیم **از طریق API رسمی موتور جست‌وجو** صفحات عمومی را پیدا کنیم. در این روش، خودِ نتیجه‌ی جست‌وجو (عنوان، لینک و خلاصه‌ای که موتور جست‌وجو برگردانده) مدرک ماست و هیچ درخواستی مستقیماً به اینستاگرام یا فیس‌بوک ارسال نمی‌شود.

## هزینه و سهمیه (بررسی سپتامبر ۲۰۲۶)
- از فوریه‌ی ۲۰۲۶ پلن رایگان کلاسیک Brave حذف شده است. کاربران جدید **۵ دلار اعتبار ماهانه** می‌گیرند که تقریباً **۱٬۰۰۰ جست‌وجو** در ماه می‌شود. بعد از آن هزینه حدود ۵ دلار برای هر ۱٬۰۰۰ جست‌وجو است.
- **Quota Guard: سقف ۸۰۰ جست‌وجو در ماه.**
- با ۱۰ شهر و ۸ دسته و حدود ۳ کوئری برای هر جفت (اینستاگرام، فیس‌بوک و وب عمومی)، هر دور کامل ایندکس ۲۴۰ جست‌وجو مصرف می‌کند؛ پس **حدود ۳ دور در ماه** ممکن است.

## الگوهای کوئری
برای هر (شهر، دسته):

| هدف | کوئری |
|---|---|
| Instagram | `site:instagram.com "{city}" ({fa_keyword} OR "{en_keyword}")` |
| Facebook | `site:facebook.com "{city}" ("{en_keyword}" OR {fa_keyword})` |
| وب عمومی | `"{en_keyword}" "{city}" -site:instagram.com -site:facebook.com` |

کلیدواژه‌ها از [06](../06-categories-and-locations.md) می‌آیند، مثلاً `Farsi speaking dentist` و `دندانپزشک ایرانی`.

## پردازش نتایج
1. از URL نوع مقصد مشخص می‌شود: پروفایل اینستاگرام (`instagram.com/{username}`، به‌جز `/p/` و `/reel/` و ...)، صفحه‌ی فیس‌بوک یا وب‌سایت
2. عنوان و خلاصه (snippet) به Detector داده می‌شود
3. اگر امتیاز حداقل «پایین» بود:
   - برای اینستاگرام، نام‌کاربری به صف [Business Discovery](instagram.md) می‌رود تا اطلاعات تکمیل شود
   - برای ادغام با مکان‌های OSM و Google، از نام و شهر استفاده می‌شود (Entity Resolver)

## نشانه‌های ایرانی بودن
`explicit_keyword`، `persian_script_text`، `iranian_food_terms` و ... از عنوان و خلاصه‌ی نتیجه

## لینک نمایش‌داده‌شده به کاربر
URL نتیجه (مثلاً `https://www.instagram.com/shirazkitchen/`)

## ذخیره‌سازی
URL، عنوان و خلاصه‌ی کوتاه ذخیره می‌شوند. طبق شرایط Brave، ذخیره‌ی نتایج در پلن‌های فعلی مجاز است؛ **این مورد قبل از پیاده‌سازی با متن فعلی قوانین تطبیق داده شود.**

## جایگزین‌ها

### بدون حساب
- **Marginalia Search API:** با کلید عمومی `public` و بدون ثبت‌نام کار می‌کند (https://about.marginalia-search.com/article/api/). ولی ایندکسش بیشتر وبلاگ‌ها و سایت‌های غیرتجاری است، کلید عمومی اغلب به محدودیت نرخ می‌خورد و برای پیدا کردن کسب‌وکار ارزش کمی دارد. **در فاز ۳ آزمایش می‌شود.** برای کلید اختصاصی رایگان باید ایمیل زد.
- **DuckDuckGo:** API جست‌وجوی وب ندارد (Instant Answer API فقط تعریف‌ها و جواب‌های کوتاه برمی‌گرداند) و اسکرپینگش هم ممنوع است ([rejected.md](rejected.md)).

### با حساب
- **Google Custom Search JSON API:** برای مشتریان جدید بسته است و ۱ ژانویه‌ی ۲۰۲۷ کاملاً خاموش می‌شود ([rejected.md](rejected.md))
- **SearXNG با میزبانی شخصی:** رایگان، ولی در عمل موتورهای دیگر را اسکرپ می‌کند؛ با [ADR-002](../decisions/002-official-apis-only.md) سازگار نیست
- موتورهای جست‌وجوی دیگر با API (مثل Mojeek و Tavily): بررسی قیمت در صورت نیاز
