# گزارش دقت Detector (فاز ۴)

- **تاریخ:** ۲۰۲۶-۰۹-۲۶
- **معیار اتمام فاز ۴:** دقت (precision) حداقل ۹۰٪ برای نتایج «اطمینان بالا» و «اطمینان متوسط»
- **نتیجه:** ✅ **قبل از اصلاح ۹۱٫۶٪ بود و بعد از اصلاح ۹۹٫۴٪ شد** (برای هر دو سطح با هم)

## روش

1. **نمونه:** ۳۰۰ کسب‌وکار نمایش‌داده‌شده (امتیاز حداقل ۰٫۲۵ و وضعیت `active`) به‌صورت تصادفی انتخاب شدند، از هر سطح اطمینان ۱۰۰ مورد، از همه‌ی ۱۰ شهر. انتخاب با seed ثابت (`20260926`) انجام شد. کل نتایج نمایش‌داده‌شده در آن لحظه: ۸۷۴ «بالا»، ۹۱۲ «متوسط» و ۳۹۵ «پایین».
2. **معیار برچسب:** تعریف [docs/04](../04-iranian-detection.md): صاحب یا کارکنانش ایرانی یا فارسی‌زبان باشند، یا محصول و خدمات ایرانی ارائه دهد. فارسی‌زبان‌های افغانستانی و تاجیک هم داخل تعریف هستند.
3. **برچسب‌زن:** این دور را **Claude** (دستیار هوش مصنوعی) برچسب زده، فقط بر اساس مدرک‌ها، منابع و لینک‌هایی که برای هر نتیجه ذخیره شده بود. لینک‌ها باز نشدند. در دیتابیس با `labeled_by = "claude"` ثبت شده‌اند و **باید یک نفر آن‌ها را در پنل ادمین (`/fa/admin/labels`) بازبینی کند.**
4. **موارد نامطمئن برچسب نخوردند:** ۵۳ مورد از ۳۰۰ (مثلاً «Pars Plumbing» یا «Zagros Grill» که فقط نامشان «ایرانی» به نظر می‌رسد و مدرک دیگری ندارند). بیشترشان از سطح «پایین» هستند. پس دقت سطح «پایین» فقط روی مواردی حساب شده که قضاوت درباره‌شان ممکن بود.

## نتیجه

| سطح | قبل از اصلاح | بعد از اصلاح | بازه‌ی اطمینان ۹۵٪ (بعد) |
|---|---|---|---|
| اطمینان بالا | ۱۰۰/۱۰۰ = **۱۰۰٪** | ۱۰۰/۱۰۰ = **۱۰۰٪** | ۹۶٫۳٪ تا ۱۰۰٪ |
| اطمینان متوسط | ۷۵/۹۱ = **۸۲٫۴٪** | ۷۵/۷۶ = **۹۸٫۷٪** | ۹۲٫۹٪ تا ۹۹٫۸٪ |
| احتمالاً ایرانی (پایین) | ۴۱/۵۶ = **۷۳٫۲٪** | ۴۱/۴۷ = **۸۷٫۲٪** | ۷۴٫۸٪ تا ۹۴٫۰٪ |
| **بالا + متوسط** | ۱۷۵/۱۹۱ = **۹۱٫۶٪** | ۱۷۵/۱۷۶ = **۹۹٫۴٪** | ۹۶٫۹٪ تا ۹۹٫۹٪ |

ستون «بعد» یعنی بعد از حذف نتایجی که اصلاح زیر آن‌ها را از نمایش خارج می‌کند. بررسی شد که **هیچ نتیجه‌ی درستی فقط به این نشانه وابسته نبود**: هر ۲۲ کسب‌وکار برچسب‌خورده‌ای که تنها مدرکشان نام فارسی OSM بود، اشتباه بودند. در زمان نوشتن این گزارش، OSM برای تورنتو، ونکوور و مونترال دوباره اجرا شده بود و ۲ مورد از آن‌ها واقعاً حذف شده بودند. بقیه با ایندکس بعدی هر شهر حذف می‌شوند.

## اشتباه‌ها و اصلاح‌ها

| علت | تعداد (متوسط / پایین) | اصلاح |
|---|---|---|
| **تگ `name:fa` در OSM:** مپرها برای پارک‌ها، فروشگاه‌های زنجیره‌ای (Penny، ALDI، H&M، Deichmann)، دانشگاه‌ها و ایستگاه‌ها ترجمه‌ی فارسی می‌گذارند | ۱۵ / ۹ | ✅ `name:fa` دیگر مدرک نیست و در کوئری Overpass هم نیست. فقط به‌عنوان نام فارسی نمایش داده می‌شود |
| دسته‌ی اشتباه در Overture («Syma's Mexican Grill» با دسته‌ی `persian_restaurant`) | ۱ / ۰ | — (خطای منبع؛ از طریق «گزارش اشتباه» قابل اصلاح است) |
| متن اردو به‌عنوان فارسی («آئینہِ لفظ») | ۰ / ۱ | ✅ حرف «ہ» (U+06C1) نشانه‌ی اردو شد |
| نام‌هایی که اسم شهر ایرانی دارند ولی ربطی به ایران ندارند (Shiraz به‌عنوان اسم کوچک، لامپ‌های PAR، ایستگاه اتوبوس خیابان Persia، دونر Zagros) | ۰ / ۴ | — (برای همین است که این‌ها در سطح «پایین» می‌مانند) |
| رستوران چندملیتی که از غذای ایرانی هم نام برده | ۰ / ۱ | — |

یک باگ دیگر هم در بررسی پیدا شد که روی دقت اثر نداشت: `gmail.com` به‌عنوان «وب‌سایت» یک کسب‌وکار ثبت شده بود. ✅ دامنه‌های ایمیل به `non_business_domains.txt` اضافه شدند.

## مشاهدات برای بعد

- **سطح «بالا» بدون خطا است.** بیشتر این نتایج یا در یک دایرکتوری ایرانی ثبت شده‌اند، یا دسته‌ی رستوران ایرانی در Overture/OSM دارند، یا وب‌سایتشان صریحاً Persian یا Farsi نوشته است.
- **نشانه‌ی `negative_keyword` برای «Afghan»** با تعریف docs/04 که فارسی‌زبان‌های افغانستانی را شامل می‌داند نمی‌خواند. در این نمونه ۶ کسب‌وکار افغانستانی درست بودند. پیشنهاد: «Afghan» از کلمات منفی حذف شود و به‌جای آن برچسب «فارسی‌زبان» بگیرد. این کار در این دور انجام نشد تا تصمیمش با صاحب پروژه باشد.
- **سطح «پایین»** عمدتاً نام‌هایی مثل Pars، Zagros، Shiraz و Yalda است که بدون مدرک دیگر قابل قضاوت نیستند. بررسی وب‌سایت (فاز ۱) همان ابزاری است که این‌ها را بالا یا پایین می‌برد. برای کسب‌وکارهایی که وب‌سایت ندارند، نمایش با برچسب «احتمالاً ایرانی» منطقی است.

## بازتولید

```bash
cd services/api
uv run python -c "from farsiyab.db import session_scope; from farsiyab.evaluation import precision; \
  s = session_scope().__enter__(); print(precision(s))"
```
یا صفحه‌ی `/fa/admin/labels` در پنل ادمین. برای دیدن اثر تغییر وزن‌ها بدون ایندکس دوباره: `evaluation.precision_with_weights(session, {"signal": weight})`.
